title: "Do programming styles evolve?"
draft: true
---

Yesterday I went to the Musée d'Art et d'Histoire in Geneva. They have a temporary exhibition about Ferdinand Hodler, a famous Swiss painter. I am no expert in art, but I cannot help but notice that although the basic materials don't seem to change much---brushes, paint, etc---the techniques, the styles have considerably evolved over the centuries. I suspect this is more or less true of most art forms.

All, save perhaps one. If we accept programming as an art form, are we seeing much change in our programming styles? And I'm not talking about programming paradigms here, which I suspect are driven more by the designers of programming languages than by the majority of professional programmers. I'm talking about the styles and techniques used within a given programming environment.

I propose the following experiment. Pick a programming environment that has been around for an appreciable amount of time, without undergoing dramatic transformations. Fortran would probably not fit: modern Fortran seems to be very different from the Fortran I was taught in college. C++ has also seen dramatic changes since the publication of the C++11 standard. Java, Python, and Ruby have seen too many changes to the language. We need something that was written 30 years ago and would still be recognizable. The best environments that come to mind would be C and S/R.
