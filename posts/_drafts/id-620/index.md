Some of you may wonder how hard (or easy) it is to write unit tests in a language that, you know, doesn't have a nice green bar. Not entirely trivial, but relatively easy nonetheless, it turned out to be. Your setup may vary, but here is the one that we found worked the best for us: $ tree -L 1 . ├── CppUTest/ ├── libneurobat/ ├── Makefile ├── README.md └── .... The \`CppUTest\` directory contains the CppUTest distribution. The \`libneurobat\` directory contains our source. We have several sub-projects loosely related to each others that we keep under the same Git repository. Many of them refer to the common algorithm code in \`libneurobat\`, and also use the CppUTest framework. Let's have a look at the directory layout for \`libneurobat\`: . ├── Makefile ├── neurobat.h ├── tests/ └── \*.{c,h} We keep the production source code at the main level in the \`libneurobat\` directory, while all the test code goes under its own \`tests\` sub-directory. That makes writing the Makefile much easier. The trick now is to use have your main \`Makefile\` include the \`MakefileWorker.mk\` file that's shipped with the CppUTest distribution. It's not entirely trivial to find it, and the documentation could, to put it charitably, be improved. Here are the relevant sections of our \`Makefile\`: SRC\_DIRS = . TEST\_SRC\_DIRS = tests CPPUTEST\_HOME = ../CppUTest INCLUDE\_DIRS = $(CPPUTEST\_HOME)/include COMPONENT\_NAME = neurobat include $(CPPUTEST\_HOME)/build/MakefileWorker.mk CppUTest: $(MAKE) -C $(CPPUTEST\_HOME) I'm omitting irrelevant details for brevity here, such as the flags we pass to the compiler etc. What's important to note here is that the \`MakefileWorker.mk\` file defines its own \`all\` target that will build an executable named according to the \`COMPONENT\` variable, in this case \`neurobat\_tests\`, which will then run all the unit tests defined under the \`tests\` directory. So this simple \`Makefile\` is in principle all you need to get started with CppUTest. As an example, here is the unit test that will verify that our implementation of the Nelder-Mead optimization algorithm properly finds the minimum of the so-called Rosenbrock function: #include <math.h> #include <string.h> #include <stdlib.h> extern "C" { #include "nelder\_mead.h" } #include "CppUTest/TestHarness.h" #define EPS 0.00001f float rosenbrock(float \*x, void\*\*) { float summand1, summand2; summand1 = x[1](http://www.goodreads.com/review/show/214962888 "and highly recommended") - x\[0\]\*x\[0\]; summand2 = 1-x\[0\]; return 100\*summand1\*summand1 + summand2\*summand2; } TEST\_GROUP(NELDER\_MEAD\_TESTS) { void setup() { } void teardown() { } }; TEST(NELDER\_MEAD\_TESTS, NelderMeadFindsMinimumOfRosenbrock) { float \*result = (float\*)calloc(2, sizeof(float)); \*result = 42.0; // or any non-zero value opt\_params params = opt\_params\_new(-2., 1., 2, EPS, 1000, rosenbrock, NULL); opt\_nelder\_mead(params, result); DOUBLES\_EQUAL(1.0, result\[0\], 0.0001); DOUBLES\_EQUAL(1.0, result[1](http://www.goodreads.com/review/show/214962888 "and highly recommended"), 0.0001); free(result); opt\_params\_free(params); } Again, non-essential details omitted for brevity. When the compilation finishes you have an \`neurobat\_tests\` executable that you can run from the command line, profile, run under Valgrind etc: $ ./neurobat\_tests ...................................
